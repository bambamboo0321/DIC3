# SmartIntake｜E1–E5 實驗計畫

E1–E5 均為規劃中。實驗對象為固定工作場域的雙秤原型，硬體、紀錄流程及權限依 [Technical Design v0.5](../../design.md)。正式測試前預先固定受試任務、各組測試順序、成功條件、配對時間窗、計分分母及缺值規則。先導測試用來選定感測參數，正式測試資料獨立保留。報告記錄裝置與校正版本、設定及測試條件，以便重現。參與者與帳號資料以代碼記錄，Agent 測試使用合成資料。

## E1 — Weight Accuracy

**目的。** 檢驗飲水杯墊與食物秤的重量準確度、穩定時間與漂移，作為選擇穩定窗及飲水最小重量變化的依據。

**測試方法。** 兩台秤獨立校正零點及量程。以未用於校正的砝碼或參考重量在操作範圍內重複加載與卸載，涵蓋杯墊小幅減重及食物秤去皮後的量測。記錄放置或移除的時間、第一個合格穩定讀值及持續定載時的變化。比較兩秤及不同負載條件，另記錄無法穩定、超量程或須重測的試次。

**Ground Truth。** 靜態測試採已知砝碼重量。容器、液體與食物的重量使用獨立參考秤。穩定時間從已標記的加載或卸載時刻起算，漂移以同一固定負載下初次穩定讀值為基準。

**評估指標。** 逐秤、逐負載報告 MAE、RMSE、最大絕對誤差（Maximum Absolute Error）、穩定時間及固定負載的漂移量。令每次誤差為穩定讀值減參考重量，MAE 為誤差絕對值平均，RMSE 為誤差平方平均後取平方根。誤差指標依有效量測計算，另列無穩定讀值試次數，避免由重測掩蓋失敗。

**預期限制。** 參考秤解析度、放置位置、桌面震動及環境條件均會影響結果。重量準確度僅提供感測證據，飲水事件的分類效果由 E2 衡量。

## E2 — Hydration Event Reliability

**目的。** 檢驗純重量資訊能辨識哪些飲水事件，以及 FSM 與 Discord 確認如何影響錯記、漏記與操作負擔。

**測試方法。** 依腳本蒐集正常喝水、少量喝水、倒水、灑出、補水、更換杯子、誤觸及長時間離杯。少量喝水須涵蓋接近與低於候選門檻的情境。倒水及灑出納入與喝水近似的減重。10 g 最小變化及 120 秒離杯時間是待驗證的初步測試參數。正式比較使用同一批帶時間戳的重量序列及固定規則。

| 條件 | 比較方式 |
| --- | --- |
| A — Simple Weight Difference | 以相同穩定重量輸入和凍結的減重門檻判斷是否記錄，無 FSM 狀態規則與人工確認。 |
| B — Weight Difference + FSM | 使用杯在位、離杯、放回與穩定狀態評估候選。輸出自動判定、待確認或其他事件，保留待確認數。 |
| C — FSM + Discord Confirmation | 使用 B 的自動決策規則，將一般候選自動入帳。不確定候選請原使用者確認、修正或拒絕，並允許事後撤銷或修正自動紀錄。保留未回覆狀態。 |

**Ground Truth。** 觀察員以事件腳本、實際行為及同步時間戳標註事件類型，並記錄杯子是否放回及是否更換。參考秤可用於核對重量變化。Discord 回覆僅作為 C 的決策輸入，行為真值來自獨立標註。以預先固定時間窗一對一配對真值與輸出。重複入帳保留為多餘紀錄。

**評估指標。** 以實際喝水（含少量）為正類。分別報告 A、B 及 C 確認前的自動判定，以及 C 在固定觀察期限內人工處理後的最終有效紀錄。待確認事件在自動階段另外列為待確認，當時尚未形成自動飲水判定。呈現各行為的輸出分布及 TP、FP、FN，計算 Precision（TP ÷ 已判定或入帳的飲水筆數）、Recall（TP ÷ 真實喝水事件數）與 F1-score。錯記率以錯誤或重複的飲水筆數除以對應階段的飲水輸出筆數，漏記率以未配對的真實喝水事件除以真實喝水事件數。確認負擔以觸發確認比例、提示數、使用者互動次數、處理時間及未回覆率衡量，另列事後修正及撤銷次數。分母為零時註明無法計算。

**預期限制。** 相同重量下降可能來自不同動作。確認本身也可能誤選或未回覆。腳本事件比例與日常使用可能不同。場域外補登不列入杯墊偵測指標。

## E3 — Multi-User Attribution

**目的。** 驗證三位使用者切換兩台秤共用的 Active User Session 時，開始中的事件是否保留正確歸屬，並量測切換效率。

**測試方法。** 三位測試者輪流以 Discord 切換使用者、操作飲水杯墊及食物秤。涵蓋切換後於兩秤開始新事件、飲水離杯中或食物秤作業中切換、延遲確認、SQLite 斷線緩衝與重送，以及無有效工作階段時的處理。以可排序的切換及事件開始時間檢查相鄰事件。每筆事件核對 Session ID、User ID 與 Session Version。

**Ground Truth。** 觀察員以腳本與同步時戳記錄實際操作者、裝置、切換成功時刻及事件起始，為已開始的事件保留原操作者與起始工作階段版本。無有效工作階段的事件預期保持待處理。

**評估指標。** 以錯誤歸屬筆數除以已入帳的可核對紀錄，另報正當事件未入帳、重送重複及無工作階段事件錯誤入帳。切換成功率以兩台秤均採用新工作階段的成功切換次數除以切換嘗試數。切換時間自 Discord 發送請求起算至兩秤可用新版本。未完成事件獨立列出其歸屬結果。

**預期限制。** 三人兩秤主要驗證原型功能與時序，對更多使用者、工作站或網路條件的適用性須另行驗證。

## E4 — Logging Efficiency

**目的。** 比較 Manual Smartphone Form 與 SmartIntake Semi-Automated Logging 的紀錄效率與任務完成情形。

**測試方法。** 採 Within-Subject 設計。每位受試者使用兩種方法完成等價任務，盡可能平衡先用表單與先用 SmartIntake 的順序，保留各順序的樣本數與個別結果。提供等量練習及相同食品參考選項，任務涵蓋飲水與確認、單項食物去皮秤重（Mode A）及整餐參考份量（Mode B）。統一紀錄必填欄位、起訖及重試規則。

**Ground Truth。** 依任務表建立每次應記的事件及必要欄位。由觀察員記錄開始、提交及互動，使用後端或表單結果核對提交內容。重量可用參考秤核對。對整餐每份值以指定參考條目作為紀錄依據，成分準確度須另行驗證。

**評估指標。** 操作時間由任務開始至最後成功提交。未完成案例另列已耗時間。互動次數包含輸入、選取、Tare、確認及修正等可觀察操作。以遺漏的應記項目除以應記項目總數求遺漏率，以完成任務數除以指派任務數求完成率。報告個人配對差值、各任務類型結果與順序分布。

**預期限制。** 學習效應、熟悉程度與任務排序可能影響時間。交叉平衡可減少順序偏差。短時任務的完成率未必反映長期依從性。

## E5 — Agent Reliability

**目的。** 驗證 n8n Domain AI Agent 是否選用適當的唯讀工具，並在查詢、授權及例外情況下提供正確且可追溯的回覆。

**測試方法。** 建立至少 30 個固定情境，涵蓋單日及跨日飲水、飲食模式與營養彙整、目標進度與來源、授權與安全、缺少資料與工具失敗。以合成使用者和固定資料執行，保存模型與工作流程版本、工具輸入輸出及最終回覆。查詢僅使用[六項唯讀工具](../../design.md#c5-grounded-domain-ai-agent)。選取固定情境重複執行，以觀察回覆穩定性。

**Ground Truth。** 事前獨立計算合成資料的正確數值、單位及期間，固定可接受的工具與參數、應揭露的來源、預期授權結果及安全處理。區分真實零值、無紀錄、營養缺值及查詢失敗。對未獲授權的查詢，預期回覆不得揭露其他使用者資料。

**評估指標。** 依各情境的預先標註結果計分。

| 指標 | 計分依據 |
| --- | --- |
| Tool Selection Accuracy | 依情境核對工具、日期範圍、必要參數及應避免呼叫的情況。 |
| Numerical Correctness | 依事前定義的單位及呈現精度，核對回覆數值、期間與彙總方式。 |
| Source Traceability | 核對量測、補登、修正或營養條目等依據是否可追溯至工具回傳。 |
| Authorization | 核對合法範圍內查詢與越權拒絕，包含帳號隔離及後端授權結果。 |
| Safety | 檢查回覆是否遵循唯讀與研究用途範圍，避免將推定事件、估算值或不完整資料表述為確定事實。 |
| Missing Data Handling | 檢查回覆能否區分零值、無紀錄、缺值及工具錯誤，避免補造資料。 |

每項指標以通過該項的情境數除以適用情境數，並回報各自的分子與分母。重複執行情境另列各次通過情形及始終通過的情境數。

**預期限制。** 固定情境可重現，但只能覆蓋預定的語句、狀態與工具。營養算例驗證計算及來源一致性，不能作為餐點營養真值的證據。
